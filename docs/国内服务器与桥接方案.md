# 国内服务器与桥接方案

肉垫本 2.3 的手机端仍然先写本地 Drift。下面是以后把 `server/` 放到国内云上的建议，不购买、不创建任何付费资源。

## 为什么用国内云

- 国内 App 如果用境内域名提供服务，网站和 API 域名需要 ICP 备案。备案主体和服务器都在同一家国内云上最省事。
- 猫咪照片和同步请求走国内链路，延迟比绕到海外机房低，弱网下增量同步更稳。
- 安卓提醒要走小米、华为、荣耀、OPPO、vivo 的厂商通道，这些平台的回执和 SDK 都默认对接国内服务器。APNs 仍给 iPhone，证书放在同一套 API 后面即可。

## 首选：阿里云

| 部分 | 建议 | 价格量级（按量或入门包，会变） | 说明 |
| --- | --- | --- | --- |
| ECS | 2 核 4 GB，系统盘 40 GB | 大约每月几十到一百多元 | 跑 Docker Compose 里的 API 和 Nginx |
| OSS | 标准存储，照片走预签名上传 | 存储大约每 GB 每月一角左右，外加少量请求费 | App 不经过 API 转存大图 |
| RDS PostgreSQL 或 PolarDB | 1 核 2 GB 入门 | 大约每月一两百元起 | 比自己在 ECS 里养数据库省备份和故障切换 |

备案：ECS 或备案服务在阿里云提交，域名先在国内解析。审核通常按工作日计，个人和企业材料不同。稳定性：ECS 选同地域多可用区，RDS 开自动备份。API 和数据库放同一地域（例如华东），不要把 OSS 放到另一个国家。

## 备选：腾讯云

| 部分 | 对应产品 | 价格量级 | 说明 |
| --- | --- | --- | --- |
| CVM | 同样 2 核 4 GB | 与阿里云入门机接近 | 跑同一套 Compose |
| COS | 对象存储 | 与 OSS 同量级 | 预签名上传，接口字段不变 |
| 云数据库 PostgreSQL | 入门规格 | 与 RDS 同量级 | `DATABASE_URL` 换连接串即可 |

选腾讯云的理由通常是已经有备案主体、或者推送和即时通信也放在腾讯云。没有这层关系时，用阿里云这一套就够。

两家都不建议把 Postgres 只放在 ECS 本机磁盘上当正式库。本仓库的 Compose 把数据库和 API 放在一起，是为了本机和预发能一次拉起。

## 代码里的桥接

- App：`--dart-define=API_ENV=local|staging|prod`，或用 `API_BASE_URL` 覆盖。默认 local 是 `http://10.0.2.2:8094`（安卓模拟器访问宿主机）。
- 后端：`server/docker-compose.yml` 起 API、Postgres 16 和 Nginx。对外端口 8094。
- 上传：`POST /v1/uploads/presign` 现在返回 OSS 形状的 mock 地址（`provider: oss-mock`）。换成阿里云或腾讯云时，只改服务端签名，App 仍按 `method`、`uploadUrl`、`headers` 去 PUT。
- 推送：`POST /v1/devices/push` 接受 `xiaomi`、`huawei`、`honor`、`oppo`、`vivo`、`apns`、`fcm`，先把 token 存下来，`channel` 为 `reserved`。厂商密钥以后再配，不在这个仓库里放真实密钥。

## 冲突

手机先落库。联网且设置里有 `cloudToken` 时，出站队列才推送，再按 `since` 拉取。`updatedAt` 较新的留下；时间相同则 `deviceId` 字典序更大的留下。删除用 `deletedAt`，旧删除不会盖掉新修改。
